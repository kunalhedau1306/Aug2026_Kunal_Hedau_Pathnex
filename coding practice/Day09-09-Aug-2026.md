## 1. AWS Shield

AWS Shield is a managed DDoS protection service.

### Shield Standard
Provides automatic baseline protection against common network and transport-layer DDoS attacks for AWS resources such as CloudFront, Route 53 and Elastic Load Balancing.

### Shield Advanced
Provides enhanced DDoS protection, additional visibility and response capabilities, and DDoS cost protection for eligible resources.

```text
Internet
   |
   v
AWS Shield
   |
   v
Application
```

### Shield vs WAF

| Shield | WAF |
|---|---|
| DDoS protection | Web application firewall |
| Protects against DDoS | Filters HTTP/HTTPS requests |
| Network/transport DDoS focus | Application-layer filtering |
| Shield Standard is automatic | Rules are configured |
| Works with WAF | Can use managed/custom rules |

**Memory:** Shield = DDoS protection; WAF = web request filtering.

Internet

WAF can work alongside Shield.

## 3. Cross-Site Scripting (XSS)

XSS is a web application vulnerability where an attacker causes malicious client-side content, commonly JavaScript, to execute in another user's browser.

### Types

**Stored XSS:** malicious content is stored by the application and later served to users.

**Reflected XSS:** malicious input is reflected immediately in a response.

**DOM-based XSS:** unsafe client-side JavaScript processing causes the vulnerability.

### Prevention
- Output encoding
- Input validation
- Context-aware escaping
- Content Security Policy
- Secure framework practices

**Memory:** XSS → browser/client-side script.

---

## 4. SQL Injection

SQL injection occurs when untrusted input changes the intended SQL query.

```text
User Input
    |
    v
Application
    |
    v
SQL Query
    |
    v
Database
```

Potential impact:
- Unauthorized data access
- Data modification
- Data deletion
- Authentication bypass

### Prevention
- Parameterized queries
- Prepared statements
- Safe ORM usage
- Input validation
- Least-privilege database accounts
- Secure error handling

**Memory:** SQL Injection → database query manipulation.

---

## 5. XSS vs SQL Injection

| XSS | SQL Injection |
|---|---|
| Targets browser/user context | Targets database interaction |
| Injects client-side content/script | Manipulates SQL |
| Commonly affects web pages | Commonly affects database operations |
| Client-side impact | Server/database-side impact |

## 6. Amazon GuardDuty

GuardDuty is a managed threat detection service that continuously analyzes relevant AWS activity and data sources for potentially malicious or suspicious behavior.

It produces security findings.

Examples:
- Suspicious API activity
- Possible credential compromise
- Suspicious network behavior
- Malware-related indicators
- Cryptocurrency-related activity

**Memory:** GuardDuty = “Is something suspicious happening?”

## 7. Amazon Inspector

Amazon Inspector is a vulnerability management service that helps identify software vulnerabilities and unintended network exposure in supported AWS workloads.

It can assess supported resources such as:
- EC2 instances
- Container images
- Lambda functions

**Memory:** Inspector = “What vulnerabilities or exposures exist?”

## 9. CVE

CVE means **Common Vulnerabilities and Exposures**.

A CVE is a standardized identifier for a publicly known vulnerability.

Example:

```text
CVE-YYYY-NNNN
```

**Memory:** CVE = Which vulnerability?

---

## 10. CVSS

CVSS means **Common Vulnerability Scoring System**.

It provides a standardized method for expressing vulnerability severity.

Scores range from 0.0 to 10.0.

| Score | Severity |
|---:|---|
| 0.0 | None |
| 0.1–3.9 | Low |
| 4.0–6.9 | Medium |
| 7.0–8.9 | High |
| 9.0–10.0 | Critical |

**Memory:** CVSS = How severe?

### CVE vs CVSS

```text
CVE  -> vulnerability identifier
CVSS -> severity score
```

When prioritizing vulnerabilities, do not rely only on CVSS. Also consider exploit availability, internet exposure, asset criticality, active exploitation, business impact and compensating controls.

## 11. Amazon EventBridge

Amazon EventBridge is a serverless event bus service used to receive, filter and route events to targets.

```text
Event Source
     |
     v
EventBridge
     |
     +----> Lambda
     +----> SNS
     +----> SQS
     +----> Step Functions
```

### Components

**Event:** Something happened.

**Event bus:** Receives events.

**Rule:** Matches events using an event pattern and routes matching events.

**Target:** Destination that processes the event.

Example:

```text
EC2 state change
      |
      v
EventBridge
      |
      v
Lambda
      |
      v
Automated action
```

## 13. Amazon SQS

Amazon Simple Queue Service is a managed message queue.

```text
Producer
   |
   v
SQS Queue
   |
   v
Consumer
```

Benefits:
- Decoupling
- Buffering
- Asynchronous processing
- Resilience
- Scalable consumers

### Standard vs FIFO

**Standard:** very high throughput and at-least-once delivery model.

**FIFO:** ordering and deduplication capabilities for workloads requiring FIFO semantics.

### SNS vs SQS

| SNS | SQS |
|---|---|
| Pub/sub | Queue |
| Fan-out | Decoupling |
| Push-oriented delivery | Consumers process queued messages |
| Topic | Queue |

## 20. Relational Databases

Relational databases store data in tables with defined schemas and relationships.

```text
CUSTOMER
+----+--------+
| ID | NAME   |
+----+--------+
| 1  | Kunal  |
+----+--------+

ORDER
+----+-------------+
| ID | CUSTOMER_ID |
+----+-------------+
| 10 | 1           |
+----+-------------+
```

Common concepts:
- Tables
- Rows
- Columns
- Primary keys
- Foreign keys
- SQL
- Joins
- Transactions

Examples:
- Amazon Aurora
- Amazon RDS

| Relational | Non-Relational |
|---|---|
| Tables | Key-value/document/etc. |
| Defined schema | Flexible data model |
| SQL | Service-specific API/query model |
| Joins | Usually designed around access patterns |
| Strong relational transactions | Highly scalable access patterns |

## 23. Amazon Aurora

Amazon Aurora is a managed relational database engine compatible with MySQL and PostgreSQL and available through Amazon RDS.

Useful for:
- SQL workloads
- Relational data
- Complex queries
- Joins
- Relational transactions
- Existing MySQL/PostgreSQL applications

Simplified architecture:

```text
Application
    |
    v
Aurora Cluster
  /       Writer   Reader(s)
  \       /
   Shared Aurora Storage
```

---

## 24. Amazon DynamoDB

DynamoDB is a fully managed NoSQL database providing key-value and document data models.

Characteristics:
- Serverless operation
- Low-latency access
- Automatic scaling capabilities
- High availability
- Flexible item attributes

Example:

```json
{
  "UserId": "1001",
  "Name": "Kunal",
  "City": "Hyderabad"
}
```

### Primary keys

Simple primary key:

```text
Partition Key
```

Composite primary key:

```text
Partition Key + Sort Key
```

Good key design is important for distributing workload efficiently.

---

## 25. Aurora vs DynamoDB

| Aurora | DynamoDB |
|---|---|
| Relational | NoSQL |
| SQL | Key-value/document |
| MySQL/PostgreSQL compatible | AWS-native NoSQL APIs |
| Tables/relationships | Items/attributes |
| Supports joins | No traditional relational joins |
| Structured relational schema | Flexible attributes |
| Good for relational transactions | Good for high-scale low-latency access patterns |
| RDS-managed engine | Fully managed/serverless NoSQL |

### Choose Aurora when
- You need SQL.
- You need joins.
- Data is relational.
- You need relational transactions.
- You have an existing MySQL/PostgreSQL workload.

### Choose DynamoDB when
- You need very high scale.
- You need predictable low latency.
- The data fits key-value/document modeling.
- You can design around known access patterns.
- You want serverless database operations.

## 27. Event-Driven E-Commerce Example

```text
                         Internet
                            |
                         WAF
                            |
                       Application
                            |
                       EventBridge
                            |
          +-----------------+----------------+
          |                 |                |
        Lambda             SNS              SQS
          |                 |                |
          |              Alerts          Consumers
          |
     Step Functions
          |
       +--+--+
       |     |
       v     v
    Aurora DynamoDB
```

Example flow:

1. Customer places an order.
2. Application emits an order event.
3. EventBridge receives the event.
4. Lambda performs lightweight processing.
5. SNS distributes notifications.
6. SQS buffers asynchronous work.
7. Step Functions orchestrates a multi-step process.
8. Aurora stores relational transactional data.
9. DynamoDB can store high-scale access-pattern-oriented data.

## 31. Key Takeaways

1. **Shield protects against DDoS; WAF filters web requests.**
2. **XSS primarily affects browser/client-side execution; SQL injection manipulates database queries.**
3. **GuardDuty detects suspicious activity; Inspector identifies vulnerabilities and exposure.**
4. **CVE identifies a vulnerability; CVSS expresses severity.**
5. **EventBridge routes events.**
6. **SNS provides pub/sub and fan-out.**
7. **SQS provides durable asynchronous queues and decoupling.**
8. **Step Functions orchestrates multi-step workflows.**
9. **Lambda runs serverless code.**
10. **KMS manages cryptographic keys; SSM manages systems and operational configuration.**
11. **Aurora is a managed relational SQL database.**
12. **DynamoDB is a managed NoSQL key-value/document database.**
13. **Security prioritization should consider business and environmental context, not just CVSS.**
