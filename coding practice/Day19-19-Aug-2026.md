# Day 19 – Argo CD (GitOps Continuous Delivery)

**Date:** 19-Aug-2026

## 1. What is Argo CD?

Argo CD is a declarative, GitOps continuous delivery tool for Kubernetes.

The basic model is:

```text
Git Repository
      |
      | Desired State
      v
    Argo CD
      |
      | Synchronization
      v
Kubernetes / EKS
```

Instead of manually deploying Kubernetes manifests with `kubectl apply`, the desired configuration is stored in Git. Argo CD continuously compares Git with the Kubernetes cluster and synchronizes the cluster when required.

---

## 2. What is GitOps?

GitOps is an operational model where Git acts as the source of truth for the desired state of applications and infrastructure.

Typical workflow:

```text
Developer
   |
   v
Git Commit / Pull Request
   |
   v
Git Repository
   |
   v
Argo CD
   |
   v
Kubernetes / EKS
```

Important principle:

> Git contains the desired state and Argo CD makes Kubernetes match that desired state.

# 7. Desired State vs Live State

This is one of the most important concepts.

### Desired State

What Git/configuration says should exist.

Example:

```yaml
replicas: 3
```

### Live State

What actually exists in Kubernetes.

Example:

```text
replicas = 2
```

Argo CD detects:

```text
Desired = 3
Live    = 2
```

Therefore:

```text
OutOfSync
```

---

# 8. Synced

If:

```text
Desired State = Live State
```

Argo CD reports:

```text
Synced
```

Example:

```text
Git:
replicas: 3

Kubernetes:
replicas: 3
```

---

# 9. OutOfSync

If:

```text
Git:
replicas: 3

Kubernetes:
replicas: 2
```

Argo CD reports:

```text
OutOfSync
```

Depending on synchronization policy, Argo CD can automatically correct the difference.

# 11. Argo CD Application

The central object in Argo CD is an **Application**.

An Application defines:

- Source repository
- Repository path
- Target revision
- Destination cluster
- Destination namespace
- Project
- Sync policy

Example:

```yaml
apiVersion: argoproj.io/v1alpha1
kind: Application
metadata:
  name: myapp
  namespace: argocd
spec:
  project: default

  source:
    repoURL: https://github.com/example/myapp-config.git
    targetRevision: main
    path: manifests

  destination:
    server: https://kubernetes.default.svc
    namespace: myapp

  syncPolicy:
    automated:
      prune: true
      selfHeal: true
```

# 16. Self-Heal

Suppose Git says:

```text
replicas = 3
```

Someone manually changes Kubernetes:

```bash
kubectl scale deployment myapp --replicas=1
```

Now:

```text
Desired = 3
Live    = 1
```

With:

```yaml
syncPolicy:
  automated:
    selfHeal: true
```

Argo CD can restore the desired state.

This is called **self-healing**.

---

# 17. Prune

Suppose Git contains:

```text
deployment.yaml
service.yaml
configmap.yaml
```

Later `configmap.yaml` is removed from Git.

With:

```yaml
prune: true
```

Argo CD can remove the corresponding Kubernetes resource.

Therefore:

```text
prune
→ Remove resources no longer defined in Git
```

Use pruning carefully in production.

---

# 18. Self-Heal + Prune

Common configuration:

```yaml
syncPolicy:
  automated:
    prune: true
    selfHeal: true
```

Meaning:

```text
prune
→ Remove resources removed from Git

selfHeal
→ Correct live-state drift
```

# 36. Troubleshooting

## Application is OutOfSync

Run:

```bash
argocd app get myapp
argocd app diff myapp
```

Check:

- Git revision
- Repository path
- Manifest changes
- Helm values
- Kubernetes live resources

## Application is Degraded

Check Kubernetes:

```bash
kubectl get pods -n myapp
kubectl describe pod <pod> -n myapp
kubectl logs <pod> -n myapp
```

## Repository problem

Check:

```text
Repository URL
Credentials
Network
TLS
Branch/tag
Path
Repository permissions
```

## Sync failure

Use:

```bash
argocd app get myapp
argocd app diff myapp
kubectl get events -n myapp --sort-by=.lastTimestamp
```

Then inspect the failing Kubernetes resource.

# 40. Interview Questions

### What is Argo CD?

A declarative GitOps continuous delivery tool for Kubernetes.

### What is GitOps?

Using Git as the source of truth for desired application/infrastructure state.

### What is desired state?

The configuration that should exist, normally represented in Git.

### What is live state?

The actual state of resources currently running in Kubernetes.

### What is OutOfSync?

The desired state and live state differ.

### What is Synced?

The desired and live states match.

### What is self-heal?

Automatic correction of certain live-state changes that differ from the desired state.

### What is prune?

Removing Kubernetes resources that are no longer defined in the desired configuration.

### Can Argo CD deploy Helm charts?

Yes.

### Does Argo CD replace Helm?

No. Helm handles packaging/templating while Argo CD handles GitOps delivery and reconciliation.

### Does Argo CD replace Jenkins?

No. Jenkins is commonly used for CI, while Argo CD focuses on Kubernetes CD/GitOps.

### What is an Argo CD Application?

A custom resource defining the source and destination for a Kubernetes application.

### What is drift?

A difference between desired state and live Kubernetes state.

### How can you troubleshoot OutOfSync?

Use:

```bash
argocd app get myapp
argocd app diff myapp
```

and inspect the Git configuration and live Kubernetes resources.

```text

 ↓
Compare
 ↓

 ↓

 ↓

```

**Core concepts to remember:**

```text

Argo CD = GitOps CD / Reconciliation

Application = Argo CD deployment definition

Synced = Desired state matches live state

OutOfSync = Desired state differs from live state

Self-Heal = Correct live drift

Prune = Remove resources deleted from Git

Helm = Packaging / templating

EKS = Kubernetes platform
```
