# DevSecOps — Detailed Notes
**Date:** 30-Aug-2026

## DevOps to DevSecOps
Traditional delivery often builds and deploys first, then performs security checks later. DevSecOps makes security a continuous responsibility: **build, deploy, and stay secure**. It shifts checks left into development and pipelines, and continues protection through runtime monitoring.

~~~mermaid
flowchart LR
 C[Code]-->B[Build]
 B-->S[Security scans]
 S-->T[Test]
 T-->D[Deploy]
 D-->R[Runtime monitoring]
 R-->C
~~~

## Security testing types
| Control | Finds | Example tool |
|---|---|---|
| SAST | Insecure code patterns, SQL injection, unsafe APIs | SonarQube |
| SCA | Known CVEs in third-party/open-source dependencies | SonarQube/SCA platform |
| Secret scanning | Passwords, tokens, private keys committed to code | Pipeline secret scanner |
| Container scanning | Vulnerable OS packages and libraries in images | Trivy |
| IaC scanning | Risky Terraform/Kubernetes/cloud configuration | Checkov |
| DAST | Runtime weaknesses by testing the running application | OWASP ZAP |

## SAST
Static Application Security Testing analyses source code without running it. It can identify injection risks, hard-coded secrets, weak crypto, unsafe deserialization, and poor input validation.

SAST findings require triage: a tool result is not automatically exploitable. Fix confirmed high-severity findings, add tests, and use a documented exception with expiry only where risk acceptance is approved.

## SCA
Software Composition Analysis inventories dependencies and checks their versions against known vulnerabilities. Maintain lock files/SBOMs, update vulnerable packages, and remove unused dependencies. A CVE must be assessed for reachability and compensating controls, but should never be ignored merely because it is in a transitive library.

## Container and Kubernetes security
Scan images before registry promotion. Use small trusted base images, pin versions/digests, run as non-root, remove build tools/secrets, and rebuild frequently. For Kubernetes, check privileged containers, host mounts, exposed services, missing resource limits, weak network policies, and unsafe RBAC.

## Secret scanning
Scan commits and CI logs for passwords, API tokens, connection strings, certificates, and private keys. If a secret is exposed, revoke/rotate it immediately; deleting the commit is not enough because repository history and logs may retain it. Store secrets in an approved secret manager, not in Git, Docker images, Terraform variables, or tickets.

## IaC security with Checkov
Infrastructure-as-Code scanning detects insecure Terraform, CloudFormation, Kubernetes manifests, and similar definitions before resources are created. Typical checks include public storage, open security groups, unencrypted disks/databases, missing logging, and overly broad IAM permissions.

~~~bash
checkov -d infrastructure/
~~~

## DAST with OWASP ZAP
Dynamic Application Security Testing behaves like an attacker against a running, authorized test environment. It can identify missing security headers, weak session handling, injection points, exposed paths, and configuration weaknesses.

Never run active DAST against production without explicit authorization and scope. Use ACC/TST-like environments and test accounts/data.

~~~bash
docker run --rm -t owasp/zap2docker-stable zap-baseline.py \
  -t https://test.example.com
~~~

## Tool mapping
| Tool | Primary use | Pipeline stage |
|---|---|---|
| SonarQube | Code quality, SAST, quality gates | Build/pull request |
| Trivy | Container images, filesystems, IaC, vulnerabilities | Build and release |
| OWASP ZAP | DAST of deployed web applications | Post-deploy test |
| Checkov | IaC misconfiguration | Pull request/build |

## Practical CI/CD security flow
1. Developer commits code; pre-commit/PR checks detect secrets and basic issues.
2. Pipeline builds and runs unit tests plus SonarQube SAST/quality gate.
3. SCA identifies vulnerable dependencies and generates an SBOM.
4. Image is built, then Trivy scans it before registry promotion.
5. Checkov scans Terraform/Kubernetes definitions.
6. Deploy to a controlled lower environment.
7. Run OWASP ZAP baseline/approved DAST scans.
8. Promote only when defined severity gates, exceptions, and evidence are satisfied.
9. Monitor production; patch vulnerabilities and rotate exposed secrets continuously.

## Severity and gates
Block promotion for confirmed critical vulnerabilities, exposed secrets, and high-risk internet-facing misconfigurations. Define a risk-based exception process with owner, compensating control, expiry date, and remediation plan. Do not create permanent suppressions.

## Key takeaways
1. DevSecOps embeds security in delivery and runtime, not at the end.
2. SAST checks code; SCA checks dependencies; DAST tests a running application.
3. Trivy scans containers/vulnerabilities; Checkov scans IaC; SonarQube helps enforce code quality/security; OWASP ZAP performs DAST.
4. Secrets require immediate rotation when exposed.
5. Automated gates need human triage, risk ownership, and auditable exceptions.
